# adrkit-timeseries

Библиотека численных задач и обработки временных рядов. Python-пакет `adrkit`
содержит уравнение переноса, диффузии и реакции, решатели и компоненты обратных
задач. Пакет `timeseries` содержит чтение данных, признаки, методы заполнения
пропусков и метрики. Их можно использовать независимо.

## Установка

Нужен Python ≥3.12. Из папки библиотеки в PowerShell:

```powershell
python -m venv .venv
& .venv/Scripts/python.exe -m pip install -c constraints-tested.txt "."
. .venv/Scripts/Activate.ps1
```

В Linux и WSL используйте `python3` и `.venv/bin/python`, затем активируйте
окружение командой `source .venv/bin/activate`.
`constraints-tested.txt` задаёт версии зависимостей для Python 3.12.14 в Windows.
Для разработки и запуска тестов вместо `"."` установите `".[test]"`.
Команды ниже используют `python` из выбранного окружения.

Для вычислений CUDA 13 можно установить `".[cuda13]"`; этот дополнительный
набор включает CuPy и пользовательские библиотеки CUDA. Обычная установка
не требует видеокарты и не импортирует CuPy. Другие совместимые сборки CuPy
устанавливаются отдельно согласно требованиям своего драйвера.
`PositiveAffineAction(..., backend="cupy")` выбирает GPU, а значение
по умолчанию `backend="numpy"` сохраняет CPU. Реализация Стрэнга и её
производных общая; это выбор арифметики, а не другой численный метод.

## Организация кода

| Каталог | Содержимое |
|---|---|
| `src/adrkit/` | Уравнение, коэффициенты, решатели, наблюдения, функционалы и оптимизация |
| `src/timeseries/` | Данные, признаки, заполнение пропусков, метрики и обработка |
| `examples/` | Короткие примеры на искусственных данных |
| `tests/` | Тесты общего API и малых численных задач |
| `docs/` | Устройство компонентов и руководства |

Коэффициенты, источники, отображения, функционалы и методы обработки задаются
отдельными компонентами. Чтение входов, сборка задачи, вычисление и запись
результатов выполняются отдельными вызовами. В устанавливаемый пакет входят
`adrkit` и `timeseries`; примеры и тесты остаются в исходной поставке.

Описание интерфейсов: [архитектура](docs/ARCHITECTURE.md),
[расширение ADR](docs/EXTENDING.md), [временные ряды](docs/TIME_SERIES.md).

`adrkit.inverse.project_nonnegative_equalities` корректирует произвольный
вектор по линейным равенствам `H @ U = d` и ограничению `U >= 0`, минимизируя
изменение относительно опоры в заданной положительной диагональной метрике.
Матрица наблюдений и её нормировка передаются пользователем. Двойственный
метод работает в пространстве строк `H`; исходные равенства и условия ККТ
проверяются отдельно с явными допусками. Непроверенное решение не возвращается
как успешное. Метод не заменяет равенства большим штрафом и не обрезает
отрицательные значения после решения системы равенств.

`adrkit.inverse.analyze_nonnegative_observations` выполняет другой вид анализа:
наблюдения имеют положительно определённую ковариацию, поэтому отклонение
`H @ U - d` входит в стоимость, а не задаётся равным нулю. Метод минимизирует
сумму квадратичного отклонения от опоры в положительной диагональной метрике
и взвешенной наблюдательной невязки при `U >= 0`. При отсутствии наблюдений
он возвращает положительную часть опоры. Возвращаемые остатки ККТ проверяют
исходный функционал; назначение физических ковариаций остаётся за приложением.

Временной источник можно собрать из `adrkit.sources.GaussianBasis` или
`P1Basis` и отображения `sampled_source_map`. Число центров или узлов задаёт
размерность коэффициентов. Оба базиса вычисляют значения, интегралы и матрицу
Грама. Подключение собственного базиса описано в руководстве по расширению ADR.
`register_source_basis` регистрирует его конструктор в текущем процессе;
`source_basis_from_record` создаёт базис по записи с полем `type`.
Для использования из конфигурации в отдельных процессах установите пакет
с точкой входа группы `adrkit_timeseries.source_bases`, как показано
в [руководстве](docs/EXTENDING.md#регистрация-пользовательского-базиса).

## Производные отображений

`adrkit.inverse.design` предоставляет критерий риска аффинного оценивателя
`affine_goal_risk`, профильную информацию `profile_information` и выбор из
конечной таблицы `select_designs`. Матрица влияния всей процедуры, ковариации,
центральное смещение и целевые метрики передаются явно. Истинные параметры
не требуются. Поддерживаются совместные корреляции данных, диагональные
ковариации и прямоугольные факторы вырожденных ковариаций.
Наихудшее смещение оценивается `robust_ball_maximum` через SVD с учётом
ненулевого центрального смещения; результат FP64 не является интервальным
сертификатом. Выбор сети относится к переданной таблице и бюджету, не к
нерассмотренным размещениям. Для нелинейной процедуры отдельно проверяется
применимость аффинного приближения.

Для совместного случайного входа с ненулевым средним используется
`joint_moment_risk(K, offset, mean, covariance)`. Она вычисляет
`E ||offset + K X||² = ||offset + K mean||² + tr(K covariance K.T)`.
Ковариация содержит все связи компонентов; допустимы её диагональ и
`CovarianceFactor`. Например, в один вход могут входить ошибки наблюдений,
направленные изменения вычисленных по ним весов и изменение физической цели.
Закон этих величин задаёт исследователь: функция не выводит его из величины
штрафа или одного уровня шума.

`MapCapabilities` явно объявляет доступные JVP, VJP и необязательную операцию
`jacobian(at)`. Полная матрица имеет форму `(codomain.size, domain.size)`:
строки и столбцы следуют координатам массивов в порядке C. Тот же контракт
используется у `GridPrediction.jacobian`. Пользовательская карта передаёт
операцию через `map_from_functions(..., jacobian=...)`. Наличие метода у
объекта без объявления способности не включает его автоматически.

Композиция предоставляет полный Jacobian, только если его объявляют все
этапы. Метод `solve_damped_gauss_newton` использует объявленную матрицу;
при её отсутствии собирает столбцы из JVP. Способ получения производной
не меняет функционал, ограниченную подзадачу или проверку Армихо.

При неразличимых с учётом внешнего округления стоимостях решатель отдельно
проверяет исходный градиент допустимого пробного шага. Если прежний допуск
уже выполнен, возвращается `step_acceptance="stationary_trial"` с указанием,
что Армихо не подтверждено. Нестационарные шаги этим правилом не принимаются;
успех по градиенту не является доказательством минимума.

`PositiveAffineAction.jvp_many` вычисляет несколько направлений за один
проход по степеням фиксированного полинома. `StrangTrajectory.iter_jvp_many`
выдаёт чувствительности `(state_size, direction_count)` последовательно
по времени, начиная с начального узла. Это позволяет сразу применять
наблюдательные веса, не сохраняя тензор всех временных чувствительностей.
`jvp_many` собирает такой тензор, когда он требуется явно. Скалярный JVP
использует тот же внутренний проход; `rate`, `degree`, исходная траектория
и нормировка аффинных весов сохраняются.

## Примеры

| Файл | Операция |
|---|---|
| [prescribed_coefficients.py](examples/prescribed_coefficients.py) | Задать коэффициенты и локальную реакцию, решить прямую задачу |
| [source_basis.py](examples/source_basis.py) | Использовать собственный базис источника |
| [observation_operator.py](examples/observation_operator.py) | Задать усреднение и его сопряжённую производную |
| [nonlinear_map.py](examples/nonlinear_map.py) | Создать нелинейное отображение с явными производными |
| [composed_regularization.py](examples/composed_regularization.py) | Составить скалярный функционал из нескольких членов |
| [custom_inverse_problem.py](examples/custom_inverse_problem.py) | Восстановить параметры двух линейных зависимостей |
| [time_series_pipeline.py](examples/time_series_pipeline.py) | Построить признаки, заполнить пропуски и вычислить метрики |
| [configuration.py](examples/configuration.py) | Собрать и решить малую задачу из JSON |

```text
python -B examples/prescribed_coefficients.py
python -B examples/time_series_pipeline.py
python -B examples/configuration.py --config examples/configuration.json
```

Остальные примеры запускаются без аргументов таким же способом. Они используют
искусственные данные и печатают результат. Для запуска примера конфигурации из
другой рабочей папки передайте абсолютные пути к скрипту и JSON.

## Тесты

```text
python -X utf8 -B -m pytest -q
```

Для разработки установите `".[test,dev]"`. Код оформляется по PEP 8,
документация функций — по PEP 257 с разделами NumPy. Единое форматирование
задаёт Black; параметры находятся в `pyproject.toml`:

```text
python -m black --check src tests examples
```
