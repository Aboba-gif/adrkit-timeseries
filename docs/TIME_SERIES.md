# Обработка временных рядов

`timeseries` загружает панель наблюдений, скрывает контрольные значения,
заполняет пропуски и оценивает ошибки. Панель имеет три оси: время, пост и канал.
Посты и каналы идут в порядке, заданном в `PanelSpec`.
Если $n_t$ — число моментов времени, $n_s$ — число постов, а $n_c$ — число
каналов, то массив значений имеет форму $(n_t,n_s,n_c)$.
Канал обозначает одну измеряемую величину с собственной единицей;
пост — идентификатор места или объекта наблюдения.

Пример с методом градиентного построения ансамбля деревьев с гистограммным
разбиением значений признаков (`HistGradientBoostingRegressor`, далее HGB),
собственными признаками и метрикой работает на небольшой синтетической панели.
Из каталога проекта его можно запустить так:

```text
python -B examples/time_series_pipeline.py
```

## Загрузка и скрытие наблюдений

`build_data(sources, panel_spec=..., anchor=...)` проверяет описание загрузки.
Чтение начинается при `DataSource.load()`. Сейчас поддерживается широкий CSV:
`InputSourceSpec` задаёт заголовки, соответствие каналов столбцам, пост, единицы,
формат времени, часовой пояс, обозначения пропуска и SHA-256 файла. Относительный
путь разрешается от абсолютного `anchor`. `PanelSpec` задаёт регулярную сетку
`[start, stop)`, её шаг и `origin`.

Загрузчик проверяет контрольную сумму, структуру CSV и объявленные посты.
При совпадении времени, поста и канала политика `duplicates="reject"` вызывает
ошибку. `first_with_quarantine` оставляет первый элемент, а следующие исключает;
эта политика требует `route="quarantine"`. Проверка дублей выполняется раньше
проверки попадания времени на сетку.

Значение с неподходящим временем в режиме `strict` вызывает ошибку, а в режиме
`quarantine` сохраняется с исходным адресом и причиной исключения. Оно не
разбирается как число. Только у допущенных значений загрузчик проверяет
`missing_values` и преобразует остальной текст в конечное число. Поэтому
нечисловой текст в исключённой записи не приводит к ошибке числового разбора.

При переходах летнего времени `dst_policy="fail"` отклоняет неоднозначное или
несуществующее время. `shift` использует правила pandas `infer` и
`shift_forward`; `infer` может не найти подходящий порядок. `drop` превращает
такие времена в `NaT`. `shift` и `drop` требуют карантинного маршрута.

`NetworkPanel` различает три случая: конечное исходное наблюдение
(`original_observed`), принятое обозначение пропуска (`raw_missing`) и отсутствие
принятого элемента (`row_present=False`). Массивы имеют форму
`(время, пост, канал)`.

`conceal` возвращает пару `MaskedInputs` и `EvaluationTruth`: выбранные
наблюдения заменяются на NaN во входах, а исходные ответы остаются отдельно.
Маска `artificial_mask` выбирает наблюдения для искусственного скрытия и
последующей оценки. Маска `mit_mask` задаёт дополнительное скрытие наблюдений
во входах обучающей выборки и допустима только при `population_kind="train"`.
Эти булевы массивы имеют форму панели и не пересекаются.
Обе маски выбирают только конечные исходные наблюдения; их значения
сохраняются в `EvaluationTruth`. Контрольные ответы не передаются в `fit`, `predict` или функции
признаков. Полученное заполнение остаётся оценкой, а не новым измерением.

## Признаки

Набор `FeatureSet` вычисляет массив `(время, пост, признак)` с именами и единицами.
`combine_features` соединяет наборы в указанном порядке. Доступность отдельного
признака определяется конечностью его значения; NaN остаётся недоступным.

```python
from timeseries.features import (
    combine_features, channel_features, availability_features,
    lag_features, calendar_features,
)

features = combine_features(
    channel_features(["pressure"]),
    availability_features(["pressure"]),
    lag_features(["temperature"], [1, 6]),
    calendar_features(["hour_sin", "hour_cos"]),
)
values = features.transform(masked_inputs, context="causal")
```

`lag_features` берёт видимые значения канала на `step` шагов сетки раньше
текущей точки. `lead_features` берёт значения на `step` шагов позже. Скрытые
значения и точки за границами панели остаются NaN; заполненные прогнозы сюда не подаются.

Календарные признаки вычисляются по григорианскому времени панели. Для годовой
синусоидальной фазы используется средняя длина года 365.2425 дня, а не длина
текущего календарного года.

`feature_from_function(names=..., units=..., transform=..., uses_future=...)`
подключает функцию, принимающую `MaskedInputs`. Она возвращает массив признаков
в исходном порядке времени и постов. `uses_future` — объявленная зависимость:
`True`, `False` или неизвестная `None`. Контекст `causal` допускает только `False`,
а `retrospective` разрешает будущие наблюдения. Для внешней функции декларацию
обеспечивает автор. Этот выбор контекста не проверяет причинность всей процедуры
обучения и прогноза.

## Методы заполнения

`build_imputer` создаёт метод по `kind` и `parameters`. Конструктор не читает
файлы и не обучает модель. Внешнее семейство задаётся парой
`ImputerFamily(validator, constructor)` и передаётся через `families`.
Проверка параметров и создание метода остаются в Python; JSON содержит запрос.

### Интерполяция

`linear` и `pchip` работают отдельно по каждому посту и каналу без обучения.
Линейная интерполяция использует позиции наблюдений; `edge_policy="nearest"`
продолжает крайнее значение, `abstain` оставляет края недоступными. PCHIP требует
двух наблюдений. Здесь PCHIP — кусочно-кубическая интерполяция Эрмита,
сохраняющая форму данных между узлами. При `edge_policy="extrapolate"` продолжаются крайние кубические
участки, при `abstain` значения вне узлов остаются NaN. Сохранение формы между
узлами не означает монотонность экстраполяции за ними. У ряда без наблюдений
заполнение недоступно. Эти методы не возвращают стандартное отклонение
(далее SD).

### Модель Калмана

`kalman_dlm` оценивает отдельную модель для каждого поста и канала. Сигнал состоит
из случайно меняющегося уровня, гармоник и авторегрессионной компоненты
первого порядка (AR(1)); наблюдение добавляет
независимый шум. `period` измеряется шагами сетки, `harmonics` задаёт число
гармоник. Начальный уровень равен среднему наблюдений всего переданного ряда,
начальная ковариация — `initial_variance * I` (по умолчанию 10).
Здесь `I` — единичная матрица размера состояния; этот размер равен
$2K+2$, где $K$ — число гармоник `harmonics`.
`initial_variance` — начальная дисперсия каждой компоненты состояния
в квадрате численной единицы ряда.

`x0` содержит пять параметров: логарифмы дисперсий уровня, сезонной компоненты
и AR-компоненты, параметр AR до `tanh`, затем логарифм дисперсии наблюдения.
В переходе каждая гармоника поворачивается на свой угол; коэффициент AR равен
`tanh(theta[3])`. При `x0=None` начальные дисперсии берутся из дисперсии
обучающего ряда с множителями 0.0001, 0.00001, 0.3 и 0.2, а начальный AR равен 0.6.

Фильтр сначала прогнозирует состояние, затем обновляет его по наблюдению.
На NaN обновление и вклад в правдоподобие пропускаются. `fit` минимизирует
отрицательный логарифм гауссовского правдоподобия методом L-BFGS-B; `maxiter` ограничивает
число итераций. Адаптер требует хотя бы два наблюдения с положительной дисперсией
в каждом ряду. Неуспешная оптимизация вызывает исключение; прежние `theta`
численного объекта сохраняются. Успех оптимизатора не доказывает глобальный максимум.

Режим `interior` применяет сглаживание Рауха–Тунга–Стрибела: обратный проход
уточняет состояния по всем наблюдениям, используя псевдообратную прогнозной
ковариации. `tail` использует прогноз до обновления по текущему наблюдению.
`head` выполняет тот же прямой проход на обращённом ряду. Из-за начального
среднего по всему ряду даже `tail` сам по себе не является прогнозом в реальном
времени. Допустимый контекст выбирает вызывающий код.

Численное ядро возвращает сигнал и модельное стандартное отклонение — квадратный
корень суммы дисперсии сигнала и дисперсии шума наблюдения. Для сигнала используется
сглаженная ковариация в `interior` и прогнозная в `head` или `tail`. Коэффициенты `theta`
считаются фиксированными; неопределённость их оценки не включена. Это SD нового
модельного наблюдения, а не условная неопределённость уже известного значения.
Адаптер сохраняет видимые значения точно и оставляет вычисленное SD. Автоматической
калибровки SD нет.

### SoftImpute

`soft_impute` последовательно укладывает каждый ряд в строки ширины
`cycle_length`, начиная с первого элемента. Последняя строка дополняется NaN.
Позиция цикла определяется шагами ряда и не привязывается к календарным суткам.
Если в каком-либо столбце матрицы нет наблюдений, адаптер оставляет пропуски
этого ряда недоступными.

Начальное заполнение использует средние столбцов. На каждой итерации наблюдения
сочетаются с текущим заполнением, затем сингулярное разложение (SVD)
уменьшает сингулярные числа на `lam`
до неотрицательных значений и сохраняет не более `rank_max` компонент.
Критерий — половина суммы квадратов ошибок в наблюдаемых позициях плюс `lam`,
умноженное на сумму сохранённых сингулярных чисел. Его значения записываются
в `history`. Итерации заканчиваются при малом изменении критерия относительно
`tol` либо по `max_iter`; ограничение ранга не даёт обещания глобального минимума.
В результат переносятся только пропущенные позиции. SD не вычисляется.

### HGB

`hgb` обучает отдельный `HistGradientBoostingRegressor` для целевого канала
каждого поста. `HGBParameters` задаёт сдвиги и дополнительные каналы. Имена
`calendar` обозначают уже переданные столбцы, а не вычисление календаря.
Для собственного набора признаков используйте `hgb_family(features, context=...)`
и передайте семейство под выбранным именем через `families`.

При обучении встроенного HGB сдвиги берутся из исходных видимых значений,
сохраняя NaN. При заполнении перед сдвигом к прошлым значениям (`lag`)
продолжается последнее наблюдение (`ffill`), а перед сдвигом к будущим
значениям (`lead`) — следующее (`bfill`). Прогнозы обратно в признаки
не подаются. Внешний `FeatureSet` используется одинаково при обучении и прогнозе
без такого продолжения. Для каждого оценщика из переданного `Generator`
получается отдельное целое значение `random_state`.

Оба варианта поддерживают `max_iter`, `learning_rate`, `max_leaf_nodes`,
`l2_regularization`, `min_samples_leaf` и `early_stopping`. HGB заполняет только
целевой канал; остальные сохраняются. SD не вычисляется.

## Результат и оценка

Общие методы сохраняют переданную числовую шкалу: перевод единиц,
логарифмирование и ограничения значений задаёт задача. В `prediction` допустимы
отрицательные значения, а NaN означает недоступный прогноз.
`result_from_inputs(masked_inputs, prediction, ...)` создаёт результат и выводит
его доступность и статусы, если они не переданы явно. Видимые наблюдения должны
быть уже сохранены точно; функция проверяет их и копирует массивы.

Необязательный `uncertainty` означает стандартное отклонение в единицах
соответствующего канала. Допустимы неотрицательные значения и NaN; `None`
означает отсутствие оценки. Внешний метод отвечает за смысл SD. Проверка формы
и знака не делает произвольную дисперсию или числовой показатель стандартным
отклонением. Метаданные результата связывают его с панелью, временем, протоколом
и выборкой; при оценке и записи они должны совпадать.

`build_metrics()` по умолчанию создаёт корень из средней квадратичной ошибки
(RMSE), среднюю абсолютную ошибку (MAE) и среднюю знаковую ошибку (`bias`);
можно выбрать среднюю квадратичную ошибку (MSE) или
добавить `MetricFamily`. Обычная функция подключается через
`metric_from_function(name, calculate, unit=...)`. Она получает отдельные
конечные одномерные векторы ответов и прогноза без права записи и возвращает
конечное вещественное число. Для пустой группы результат равен `None`.

Для $n\geq1$ сравниваемых пар встроенные метрики вычисляются по формулам

$$
\operatorname{RMSE}=\sqrt{\frac1n\sum_{i=1}^n(p_i-y_i)^2},\qquad
\operatorname{MAE}=\frac1n\sum_{i=1}^n|p_i-y_i|,
$$

$$
\operatorname{bias}=\frac1n\sum_{i=1}^n(p_i-y_i),\qquad
\operatorname{MSE}=\frac1n\sum_{i=1}^n(p_i-y_i)^2.
$$

Здесь $n$ — число сравниваемых пар; $i\in\{1,\ldots,n\}$ — индекс пары;
$y_i\in\mathbb R$ — конечное контрольное значение;
$p_i\in\mathbb R$ — конечный прогноз в той же единице и для той же точки.
Положительная `bias` означает, что прогноз в среднем превышает контрольные
значения. RMSE, MAE и `bias` выражаются в единице канала, MSE — в её квадрате.
При $n=0$ формулы не применяются, а возвращается `None`.

Оцениваются точки, выбранные `target_mask`, с конечным ответом и доступным
прогнозом. Встроенные метрики дают им равные веса; формулу и веса пользовательской
метрики задаёт её `calculate`. Отдельно возвращаются числа запрошенных, известных,
доступных и оценённых точек. `by_channel` содержит ошибки по каналам,
`by_site_channel` — по постам и каналам. Общие ошибки возвращаются для одного
канала; для нескольких равны `None`. Каналы не объединяются по названию единицы.

`unit="channel"` обозначает единицу канала, `"channel_squared"` — её квадрат;
другая строка задаёт фиксированную единицу результата. Эти обозначения не
переводят данные и не проверяют размерность пользовательской формулы.

## Сборка и сохранение

`assemble` принимает `data={sources, panel}`, `imputer={kind, parameters}`,
`protocol_id` и `population_id`. Он создаёт описание данных и метод;
маски и следующие стадии задаются отдельно.

`build_pipeline` собирает метод и метрики. `run` обучает метод один раз на
`train`, затем использует сохранённое состояние для `calibration`, `test`
и `export`. Неиспользуемые стадии задаются `None`; у метода без обучения
`train=None`. Такой метод предоставляет `no_fit_state`; `run` передаёт это
значение в `predict` через `fitted`. Диапазоны `train`, `calibration` и `test` не пересекаются, но их
хронологический порядок не проверяется. `export` может пересекаться с ними.
Стадия с именем `calibration` здесь вычисляет прогноз и метрики, не калибруя SD.

Для записи нужен новый абсолютный `output_root` вне каталогов источников.
CSV содержит время, пост, канал, прогноз, маски и статусы. Если SD передано,
оно записывается как есть в столбец `standard_deviation`. При `None` столбца нет,
а NaN сохраняет недоступность оценки. Обученное состояние в файлы не записывается.
`pipeline.json` сохраняет исходный проверенный запрос метода; нормализованные
параметры с умолчаниями доступны в объекте метода и его состоянии.

При исключении записи созданные этим вызовом файлы удаляются по возможности;
родительские каталоги могут остаться. Запись не атомарна при аварийном завершении.
